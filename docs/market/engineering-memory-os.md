# Why Engineering Memory OS

cognibrain is positioned around coding-agent memory, not generic personal notes or chatbot personalization.

The product claim is narrow: capture corrections, review feedback, repo policies, architecture decisions, tool outcomes, and codebase changes, then retrieve the right evidence before the next patch. The proof surface is CogniCodeBench plus evidence packs, action guards, patch evidence trails, and connector telemetry.

## Claim Boundary

This page supports the Engineering Memory OS category claim when `npm run benchmark:cognicode`, `npm run verify:status`, and `npm run audit:plan1_3` pass. It does not claim managed SaaS readiness or broad coding-agent autonomy.

## Why It Matters

- Coding agents repeat mistakes when corrections stay in chat history instead of durable, scoped memory.
- Repositories need branch, package, directory, file-pattern, and harness scope, not just user facts.
- Teams need evidence trails so they can see which memories influenced a patch.
- Benchmarks should measure correction carryover, repeated mistake avoidance, procedure recall, tool-outcome learning, stale-memory suppression, and evidence correctness.
