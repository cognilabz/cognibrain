# Marketing Claim Rules

The canonical claim map lives in [`../claims.md`](../claims.md). This page exists for launch, README and website copy reviews.

## Required Pattern

Every public sentence that makes a product, benchmark, production or connector claim must include or link to a claim ID:

- `CB-CLAIM-CONTEXT`
- `CB-CLAIM-GUARD`
- `CB-CLAIM-PLANNER`
- `CB-CLAIM-EVIDENCE`
- `CB-CLAIM-PATCH-EVIDENCE`
- `CB-CLAIM-MCP`
- `CB-CLAIM-COGNICODE`
- `CB-CLAIM-ABLATION`
- `CB-CLAIM-CONNECTORS`
- `CB-CLAIM-CONNECTOR-MATURITY`
- `CB-CLAIM-STORAGE`
- `CB-CLAIM-STATUS`
- `CB-CLAIM-OBSERVABILITY`
- `CB-CLAIM-PRODUCTION`
- `CB-CLAIM-RELEASE`
- `CB-CLAIM-MARKET`

## Review Checklist

- No managed SaaS claim without a managed control-plane run.
- No benchmark leadership claim without comparable external artifacts.
- No real customer repository claim from CogniCodeBench alone.
- No vendor certification claim without fresh tenant credential smoke.
- No "production ready" language without the self-hosted boundary and release gates.
